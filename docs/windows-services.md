# Windows 系统服务

Nginx、Redis、MySQL 支持注册为 Windows 服务。Nginx 卡片的入口为“启动设置”，Redis、MySQL 为“系统服务”。PHP 无需单独注册系统服务。

Nginx 默认自动启动共享站点配置中引用的 PHP。多个网站引用同一实例时只启动一次，不同 PHP 版本可分别启动；静态站点不启动 PHP。已运行的 PHP 直接复用，不重启。所需 PHP 无法启动时，Nginx 启动会失败并提示具体实例，回收本次新启动的 PHP，保留原本已运行的实例。

“启动设置”中的两个联动选项需要停止 Nginx 后修改：

- **自动启动站点所需 PHP**：默认开启，普通启动与 Windows 服务开机启动均生效。
- **停止 Nginx 时同时停止联动 PHP**：默认关闭。关闭时，停止 Nginx 会保留 PHP；开启时只停止本次新启动的 PHP，复用的 PHP 保留。

实例卡片还提供“一起停止”；Nginx 已停止时显示“停止联动 PHP”。此操作按本次启动记录和当前进程身份检查所有权，不会停止原本已运行的 PHP 或后来手动重启的无关实例。

## 使用

1. 正常打开面板即可；需要管理员权限时，点击授权提示中的 **授权并重启**，并在 Windows UAC 中确认。也可从顶部 **以管理员重启** 主动申请。
2. 停止目标实例，进入 Nginx 的 **启动设置** 或其它组件的 **系统服务**。
3. 按需勾选 **开机自动启动**，点击 **注册服务**。注册本身不会立即启动实例。
4. 需要立即使用时，在实例卡片点击 **启动**；下次启动 Windows 时，启用开机启动的实例会自动运行，无需先打开面板。

注册后可再次进入此入口，保存开机启动设置。取消勾选会将服务设为手动启动，不会停止已经运行的实例。注销需要先停止服务；注销后实例恢复由面板管理，配置、日志和数据保留。删除实例前必须先注销。

## 状态与权限

Windows 服务列表中的显示名称为 `PHPanel · <实例名>`，内部名称为 `PHPanel-<组件>-<唯一标识>`。不同数据目录的服务名称不会冲突，管理入口会显示完整名称。卡片中的系统服务 PID 是托管程序的 PID。

服务状态来自 Windows 服务控制管理器。普通用户可以查看状态；启动、停止、注册、注销及更改启动方式需要相应 Windows 权限。操作被 Windows 拒绝时，面板会显示授权确认；点击 **授权并重启** 后使用 Windows `runas` 显示 UAC。取消授权、提权启动失败或新进程握手失败时，旧面板保持运行，现有实例不停止。

授权成功后，新进程先确认自己已获得管理员令牌，再通知旧面板退出，并等待旧进程释放数据目录。重启保留实际数据目录、页面、实例设置以及开机启动选项的草稿，随后可再次执行刚才的操作。普通实例和当前面板独占的 PHP 会随旧面板退出而停止，下载会暂停；Windows 系统服务和受其保护的 PHP 继续运行。其它未保存的编辑不会恢复。

顶部 **管理员** 状态表示当前进程已提升。此时若服务仍拒绝访问，面板会提示检查目标服务权限，不会反复申请 UAC。

系统服务默认使用 Windows 的 LocalSystem 账户。将软件放在固定、可信的本地目录；注册后保持程序、安装包和实例目录位置。移动目录前，先在原位置停止并注销服务，再在新位置重新注册。服务管理会核对托管程序路径与启动参数，发现位置变化时拒绝控制不匹配的服务。

Nginx 所有版本合计只能注册一个实例。同一已安装版本的 MySQL、Redis 只能注册一个实例，不同版本可分别注册。跨进程运行锁也会阻止面板和 Windows 服务同时运行冲突实例。

## 文件与退出行为

发行包中的 `phpanel-service.exe` 必须与 `PHPanel.exe` 放在同一目录。它会在启动时读取当前管理记录、配置及端口，不持有面板数据锁，也不写入 `state/panel.json`。每个已运行的系统服务和后台 PHP 使用独立的托管进程，并通过仅限本机的命名管道提供状态、停止和运行中扩展诊断。

退出面板时，普通实例及仅由当前面板启动的 PHP 会停止。Nginx 系统服务新启动或复用的 PHP 则继续运行，复用时保留原进程 PID；停止该 Nginx 默认也会保留 PHP。保留的 PHP 可以在实例卡片中单独停止。启动归属记录位于 `state/runtime/<nginx实例ID>.json`，每次启动使用独立标识，避免旧记录误停新进程。

后台 PHP 的配置、扩展管理和重启仍在面板中完成。更改扩展后重启会保持联动归属及退出面板后的运行行为。删除 Nginx 前，应先停止它仍托管的联动 PHP；单独注销 Windows 服务会保留实例和 PHP。

修改系统服务实例的端口前必须停止服务；保存后手动启动。服务托管程序使用现有的优雅退出流程，并用 Job Object 管理自己的进程树。Nginx 网站配置变更仍会检查配置，并重载已运行的系统服务实例。系统服务的重载通过本地命名管道交给托管进程执行，与 Nginx 主进程使用同一账户，避免面板直接发送信号时出现 `OpenEvent("Global\ngx_reload_<PID>") failed (5: Access is denied)`。通道仅允许原面板用户、管理员和 LocalSystem 访问，只接受重载操作。

升级到支持服务重载通道的版本后，需同时更新 `PHPanel.exe` 和 `phpanel-service.exe`，并停止、重新启动一次 Nginx 系统服务。旧托管进程未提供通道时，面板会提示更新并重启服务；失败仍会恢复原配置和站点记录。

启动输出位于实例的 `logs/console.log`，系统服务托管错误位于 `logs/service-host.log`，后台 PHP 托管错误位于 `logs/php-host.log`。开机启动失败时，可以从 Windows 服务管理器或实例卡片查看状态，再检查这些日志。

## 验证范围

单元测试覆盖服务注册、启动方式、注销、权限失败、状态同步、删除和端口限制、注册冲突、Nginx 重载以及运行锁。隔离的真实组件集成测试直接调用 SCM 服务处理器，验证 Nginx、Redis、MySQL 启动、面板退出后继续运行、优雅停止及管理记录不被改写。此测试不向本机注册实际系统服务；真实 SCM 注册及 Windows 重启自启动需要在管理员环境中验证。
